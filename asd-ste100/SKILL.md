# 简化技术英语

把英文技术文本改写成易于理解、执行和机器解析的表达。优先消除歧义，不追求最少字数。依据 ASD-STE100 的写作原则工作；不要声称通过本 Skill 就能获得正式标准认证。

## 选择模式

优先采用用户指定的模式；未指定时，根据原文用途选择，默认不宣布选择结果。

| 模式 | 使用场景 | 执行方式 |
|---|---|---|
| `Strict`（严格模式） | 操作步骤、工具和函数描述、报错、Agent 指令、安全说明 | 严格检查结构、术语一致性和词义；涉及正式批准词汇时核对用户提供的标准 |
| `STE-flavored`（普通技术说明模式） | README、PR 描述、变更说明、解释性文章；用户要求约 80% ASD-STE100 | 保留短句、主动表达和清晰结构；允许自然词汇，不锁死为批准词表 |

“约 80%”是非正式风格要求，不是测量值或合规分数。两种模式都以语义完整为先。

## 改写流程

1. 先理解原文。记录主体、动作、对象、条件、例外、数字、范围和要求强度。
2. 逐句检查结构。遇到长句、主语不明、动作名词化、术语混用或多个指令，按下表改写。
3. 保留信息强度。不得把 `may`、`might`、`could`、`should`、`must`、`sometimes` 等限定词删成确定事实或更强命令。把冗余套话与真实不确定性分开。
4. 对照原文复核。不得补入原因、频率、机制、效果或新的操作步骤。若用户另行要求建议，将新增内容明确标为建议。
5. 交付改写文本。无法缩短而不丢失精度时保留原句，并说明具体原因。原文已经清晰时，不强行改动。

| 检查项 | 改写要求 |
|---|---|
| 主体与语态 | 优先主动语态；原文未说明执行者时，不编造执行者。描述性文本中主体未知或无关时允许被动语态 |
| 一句一项指令 | 拆开多个动作，保留执行顺序、依赖和条件 |
| 句长 | 操作指令争取不超过 20 个英文词，描述争取不超过 25 个；必要限定条件不能为了达标而删除 |
| 简单时态 | 优先简单时态；完成时若表达当前状态，或属于 `may have failed` 等不确定表达，保留其含义 |
| 动作表达 | 用动词表达动作；例如将 `perform an analysis` 改为 `analyze` |
| 短语动词 | 用含义明确的普通动词替代含糊短语；例如将 `spin up` 改为 `start` |
| 标点和结构 | 将分号连接的内容拆成独立句；不一律禁止破折号。每段一个主题，通常不超过六句 |
| 名词堆叠 | 超过三个词的名词组合优先展开关系，保留技术名称的精度 |
| 术语一致 | 同一对象或动作使用同一名称；不同概念不能因为属于近义词就强行合并 |
| 完整表达 | 明确必要的主语、动词、冠词和条件；步骤或复杂条件用列表表达，补全以 `and` 或 `or` 结束的残句 |
| 宣传措辞 | 删除无信息的修饰；涉及原文实质承诺时保留承诺或标记缺少依据，不编造量化结果 |

阅读 [规则与适用边界](references/writing-rules.md) 核对规则解释。需要改写示例或检查语义漂移时，阅读 [改写示例](references/examples.md)。

## 使用结构检查脚本

需要批量检查英文或提供可复现的结构检查时，运行本 Skill 目录下的脚本。脚本只依赖 Python 标准库。

```bash
python3 scripts/ste-lint.py input.md
python3 scripts/ste-lint.py --json input.md
python3 scripts/ste-lint.py --baseline 5 input.md
python3 scripts/ste-lint.py --disable passive-voice,present-perfect input.md
python3 scripts/ste-lint.py --help
python3 scripts/ste-lint.py --selftest
```

省略文件参数时从标准输入读取。多个文件分别检查术语，最后合并结果。`--baseline N` 容忍 N 项硬性发现；`--disable` 接收以逗号分隔的规则标识符。硬性发现超过基线时退出码为 `1`，参数或读取错误为 `2`；被动语态和复合时态属于建议性发现，不单独导致失败。

理解结果的限制：

- 检查分号、部分短语动词、动作名词化、宣传词、长句、术语混用、列表残句、被动语态和复合时态。
- 跳过围栏代码和行内代码。Markdown 表格按单元格检查。句子仍按行和简单标点分割，位置与词数只服务于初筛。
- 统一使用 25 词阈值，不能自动识别 20 词的操作指令，也不检查名词堆叠或正式词表。
- 术语混用提示来自固定词组，不能判断两处动作是否相同；例如“检查配置”与“确认收件”可能是不同动作，需人工判断。
- 不删除或惩罚不确定表达。不比较原稿和改稿，不证明事实正确、语义等价或标准合规。零发现仅表示这些结构检查未发现问题。
- 列表识别支持行首至多三格缩进、`-`、`*`、`+`、`1.`、`1)` 和缩进行；不完整解析引用、懒惰续行或复杂嵌套结构。

不要对代码、命令、路径、URL、接口标识符和协议字段做语言改写。需要改变其行为时，按用户另行授权的开发任务处理。

## 输出约定

默认只输出可直接使用的改写文本，不加前言、模式声明、检查计数或结束语。未要求翻译时保留原稿语言；规则分析和说明使用中文。

为保留精度而有意保留不够简短的片段时，可以在末尾加一行：`保留原表达：<片段>，因为<不可丢失的信息>。` 没有此类取舍时不添加。

用户要求对照、解释改动或展示规则时，给出“规则｜原文｜改写”的表格。只报告实际检查结果，并指出保留片段的理由。
