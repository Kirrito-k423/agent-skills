# 教学与视觉验收

## 先满足能看懂，再追求密度

| 易误解的展示 | 必须改成 |
|---|---|
| `t0 · 1` | 单独的“token 编号 0”和“首元素值 1”；注明首元素是 `x[token,0]` |
| 无说明的 `1024B` | “通信长度 1024 字节”，并给出有效内容、块容量、flag与对齐的计算 |
| `F=[1,0]` 却不说顺序 | 标明块编号与flag含义；1是已发布，0可能是未到或消费后清零，要结合阶段说明 |
| 两张卡能跑就复制成四张卡 | 至少四个rank真实参与；独立计算卡对、队列、通知、输出与空任务 |
| 零散的红色源码行 | 函数名称、定义行、调用链、连续上下文；红色活动行与灰色上下文分开 |
| 页面不滚动就称无重叠 | 同时检查容器溢出、兄弟元素相交、文本被徽标遮住、连线压字 |
| 设置了视口便记录通过 | 每页读取实际CSS尺寸；测试函数接收明确的当前标签页句柄 |

默认页面背景为纯白 `#ffffff`。用线条、空间、字重表达层级。除用户明确指定外，不采用深色主题或灰色整页背景。

## 分阶段展示四个 rank

四卡必须在同一帧可见，可采用两行两列或四泳道。每卡只展开本阶段相关对象：输入、队列、通知、接收、输出按阶段替换；保留对象身份和可追踪关联。其他数据折叠时明确说明，并提供详情。不能把所有阶段压在每张卡内，造成只有缩小字体才能容纳。

集中路由的目标卡可能承载所有输入，必须用该场景验收最高密度。可按来源分组，但不得把聚合条数冒充逐token内容；输出位置仍来自真实模型。

## 对象与元素的流动

默认以一条具体记录为线索：输入数组 → 临时组装对象 → 发送布局 → 通信命令 → 接收副本 → 最终输出。每个对象画出组成字段和数组形状。通信阶段还应解释命令描述符中的源地址、目标地址、长度、操作类型和顺序标志，避免让数据在两个盒子之间凭空出现。

每一步把元素的上一步值、本步结束值、读／写、操作者和源码对应起来。“值不变但产生了新副本”“同值重写”“旗子清零但载荷未清”都要有不同表达。所有数组索引必须能定位到元素；长向量用确定公式及范围折叠，并提供完整展开和任意索引的值历史。把未知或尚未写入表示为明确状态，不能当成数值0。

检查至少一个跨卡token和一个本机token的完整生命周期。观察者应能回答每个元数据字段何时产生、如何保持或改写、被哪个输出数组消费；只会复述“RO→SO→done”而无法跟踪对象内部值，不算完成教学验收。

## 几何检查

1. 给本应分离的元素建立检测分组，例如卡片网格的直接子项、表格每行的单元格、代码行的行号和文本、控制条按钮。
2. 获取 `getBoundingClientRect()`，对同组的非祖先元素计算交集。容忍边框舍入的一小段误差；正常并列内容的交集宽、高都超过容差则失败。
3. 检查文字叶节点或 `Range.getClientRects()` 是否超出所属内容框；行高、换行后高度、徽标的占位和按钮长标题都应纳入。
4. 检查上、下相邻区块及源码行是否交叠。整张卡没有滚动，也可能是一个子区块越界覆盖了下一块。
5. 检查画线层、徽标、绝对定位元素是否覆盖数值与标签。优先把连线与移动粒子放进独立的传输带，确保它们不跨过数据区。
6. 对合法包含关系建立小范围例外：卡片包含内容、轨道包含粒子。记录例外理由，不能大范围忽略所有浮层或文字。
7. 读取 `html`、`body`、主容器背景颜色；纯白背景约束不能只依赖CSS文件文本判断。

使用已有浏览器工具按真实UI逐步检查。不得为了绕过验收而在测试时临时隐藏元素、缩小整页或裁切容器。

## 截图验收与复盘

在三个桌面参考视口查看：四卡输入、集中接收、选中token、新通知全部高亮、最长源码上下文、最后输出。原始截图应能直接回答：谁在发送、数字是什么、数据在哪个rank、属于哪个函数、当前哪个条件不满足。

验收记录按“页面×实际视口×阶段×预设”写明覆盖；未测项目单列。用户指出缺陷后，记录具体文件／帧、错误决策、影响、已实施修复和阻止复发的断言。不能只写“美化了页面”“加强了测试”。
