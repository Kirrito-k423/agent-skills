# 变量与术语解释

数字推导回答“这个值为什么是 4”，变量和术语解释回答“这个 M 表示什么，为什么需要它”。两种入口都要保留，不能让读者必须先知道词义才有能力选择正确的数字。

## 建立带作用域的解释记录

从当前页面和源码建立清单，不凭常见缩写表猜测当前意义。每条记录包含：

| 字段 | 应回答的问题 |
|---|---|
| 身份 | `termId`、显示形式、变量／参数／字段／概念／缩写／函数分类及别名 |
| 上下文 | 文件、函数、对象与嵌套字段、预设、步骤；同名词属于哪个作用域 |
| 含义 | 读者可理解的中文定义；缩写的可证实全称及其中文意思 |
| 当前作用 | 本实现中谁产生、谁使用、用于统计、寻址、搬运还是同步；不能只翻译名称 |
| 参数或变量约束 | 对应真实标识符、单位、shape、取值范围、容量／有效值及未写入的区别 |
| 关联值 | 当前教学参数或所选对象的值；派生值指向原数字推导，不复制另一套公式 |
| 来源 | 固定源码版本、文件／函数／行号，或官方一手资料；教学符号明确标记 |

单字母符号不一定是英文缩写。例如 `A` 可绑定源码的 `expert_alignment`，应说明这是教学页面选用的参数名，不编造以 A 开头的展开。不同文件中的 `M`、`T`、`count`、`slot` 不一定同义；使用带上下文的记录，禁止将全页面同字面强行绑定一个解释。

英文缩写的展开必须有证据；只有功能可以确认时，解释功能并标明源码未提供正式展开，不猜词。`dtype`、`shape`、函数名及 C++ 类型等也解释其当前用途；普通语法关键词可按语言语法统一解释，不能把语法提示当作具体变量的业务含义。

## 参数示例

下例仅适用于本次 DeepEP-Ascend 教学模型，不是所有通信程序的通用符号约定：

- **M**：每个来源 Rank 的最大 token 容量，绑定 `num_max_tokens_per_rank`。本例为 4 个槽，决定来源分区的容量与全局编号步长；`global_idx = source_rank × M + token_idx`。不能因为当前 T 也为 4 就把 M 说成有效输入条数。
- **T**：当前来源 Rank 的有效输入 token 数，绑定当前输入张量的 token 维。本例通常为 4，空输入预设为 0；M 仍为 4。把当前有效数与分配容量分别解释。
- **A**：专家输出的对齐要求，绑定 `expert_alignment`，单位为输出行。示例 `align(5,4)=8`；真实有效行仍为 5，其余 3 行是 padding。不是 attention 的泛化缩写。
- **SF**：Scale Factor，缩放因子；当前 FP8 路径传输 `sf_pack_t` 的原始打包位模式。说明它与 FP8 数值的关系，以及本动画是否真的解码／量化；BF16 的“无 SF”是未走该可选分支。

参数名 M、T、A、SF 本身可以聚焦和悬浮；相邻数值仍有独立数字入口。`R=4 · M=4 · T=0 · 无 SF` 中的每个名称都不能只有原生 `title`，也不能要求用户去悬浮后面的 4 才知道名称含义。

## 覆盖显示位置

清单至少覆盖：两屏的参数栏、标题、阶段说明、图例、传输说明、对象与数组字段、单位／类型／shape、完整对象与历史、源码节选及打开的完整源码页。选择器当前选中的变量要有同等的可访问解释入口；原生选项列表不能悬浮时，在选择器旁显示绑定当前对象的变量名称。

复合标识符如 `R0.recv_buffer[1,0]` 应解释 Rank 归属、真实变量、索引含义及来源分区，不只翻译成“接收缓冲区”。同一个 `slot` 出现在接收槽、专家输出槽或 SQ 位置时，根据字段路径分别解释。术语可在多处出现，每个出现位置都绑定正确上下文。

在渲染时使用稳定的 `termId / context` 绑定记录。源码可以词法分词，再依文件、函数、类型／对象和标识符进行解析；保留完整原始行文字及行号。字符串字面量、注释、关键字和变量须区分，不把英文普通词一律当作变量。未解析的实际变量与术语进入缺失清单并补齐，不能给所有未知标识符套“这是本函数的变量”后宣称覆盖。

## 浮层行为

术语和数字采用一致的悬浮、聚焦、Enter／点击固定、Esc／关闭交互，读者能同时找到“名词含义”与“当前值的推导”。悬浮不改变进度或 token 选择；参数／字段名称被点击时，不能意外触发反选记录。

浮层说明先给一两句中文定义与当前作用，再展开约束、关联值及来源。相关词提供在同一个固定详情内切换的入口或独立解释面板，避免层叠浮层遮挡。术语浮层不得依赖数值相邻或 DOM 文本正则反推身份；长数组的字段名与嵌套字段也有独立上下文。

在模态检查器中打开的浮层须位于可交互的模态范围内，验证实际点击、展开、滚动和关闭；只看见文字不代表能使用。切步、换预设或关闭检查器后清理失效状态，保留原数字推导及红色读写语义。

## 验收

1. 冻结显示术语清单及其出现位置，按“页面 × 实际视口 × 阶段 × 预设 × 表面”核对覆盖，记录未解释项。绑定记录存在还不够，要核对每次出现所用的作用域。
2. 独立检查中文定义、准确全称、真实变量、当前作用与 sourceRef。M／T、容量／有效数、接收／输出槽、SF pack／解码 scale 以及可选／缓存分支分别核对。
3. 实际悬浮至少一个单字母参数、一个英文缩写、一个对象变量、一个嵌套字段、一个源码标识符与一个历史／模态位置，读取正文与截图，不只检查 `title` 或 `data-*` 存在。
4. 检查三个实际桌面视口的浮层边界和锚点遮挡，键盘、固定详情、模态交互、切步清理、双屏共享进度及数字推导回归。
5. 用户指出漏词时，复现具体显示位置，记录“原错误 → 原因 → 补齐绑定和定义 → 新增语义与 UI 验收”。不要用大批无关数字断言掩盖词义仍缺失的问题。
