# 量化与并行改写方法

在计算工作量、判断依赖和筛选并行化方案时阅读。只采用与模块相关的模型，明确假设和不适用项。

## 工作量与数据移动

- 用 `工作量 = 调用次数 × 迭代次数 × 单次操作数` 展开嵌套循环，并将不规则边界写为求和。按数据分布报告最坏、典型或实测计数，不能把平均规模当作所有输入的事实。
- 浮点代码分别报告有效数学 FLOPs 和实际执行 FLOPs；通常 FMA 计 2 FLOPs，写明口径。整数、分支、索引及轮询另计，不把它们硬换算成 FLOPs。
- 将源码推导标为估算；编译器可能已做公共子表达式消除、不变量外提、向量化或融合。声称机器仍在重复执行时，用优化报告、生成代码或 profiler 计数补证；对动态整数等变成本操作注明位宽或分布假设。
- 写出读、写、临时结果、重复搬运、格式转换和消息数量。逻辑访问字节数、缓存层流量与内存控制器实测字节数是不同量；说明采用哪一种。
- 对跨核、跨进程、跨卡及跨机通信分别计入消息大小、次数、拓扑、争用和必要同步；峰值链路速率不能直接当作应用带宽。
- 用 `冗余比例 = (实际工作 - 选定参考的必要工作) / 实际工作` 时明确参考算法。没有可证明下界时称为“相对该参考的冗余”，不要声称理论最优。
- 分析复用的成本与生命周期：计算缓存键、命中、失效、同步、内存增长和命中率。对廉价计算，重算可能比访问共享缓存更快。

## 总工作量与关键路径

将依赖 DAG 中每个节点赋予同口径成本：操作数、伪指令数或时间。**`W` 与 `D` 必须同单位**，浮点运算数不能除以毫秒充当并行度。

```text
W = 所有节点成本之和
D = 从输入到输出的最长依赖路径成本
A = W / D
T_P >= max(W / P, D)
W / T_P <= min(P, A)
```

以上采用理想同质执行单元及可加的成本模型。操作数单位下 `T_P` 是模型步数；时间加权后才能称为时间下界。此处加速比针对**同一 DAG 的串行执行**，不代表相对另一个更优串行算法的收益。实际执行还受调度、缓存、带宽、争用及负载分布影响。异构 CPU/GPU/NPU 不能简单相加成 `P`；分阶段建模再考虑通信与重叠。

为当前程序保留真实顺序边；另外建立候选 DAG，表示解除不必要顺序或换算法后的上限。记录就绪任务数随时间的变化及最长/最短任务的工作差异；平均并行度大也可能出现长尾空闲。

若使用 Amdahl 估计，写出基线串行比例 `s` 及其测量范围：

```text
固定总工作量，串行部分不变、其余部分理想 P 路并行：
S(P) <= 1 / (s + (1 - s) / P)
```

算法重写可能同时改变工作量与串行比例，需要重算模型。不要将原实现的串行比例作为所有算法的永久限制。

## 算力、带宽与启动成本

对相同精度、指令类型及内存层级，按 Roofline 思路估计：

```text
I = 浮点运算量 F / 该层读写字节数 B
可达 FLOP/s <= min(计算上限 C, 带宽上限 BW × I)
理想执行时间 >= max(F / C, B / BW)
```

注明上限来自规格还是同环境微基准；实测可达上限仅作经验参考。有效工作 FLOPs 可反映业务效率，实际执行 FLOPs 用于硬件计算负担，避免混用。Roofline 不能单独解释依赖链、访存延迟、原子争用或小任务启动成本。

端到端模型按真实依赖累计成本：

```text
任务开销 = 创建/投递 + 序列化/传输 + 执行 + 同步/合并
完全顺序阶段：T = 各阶段时间之和
可重叠阶段：依据时间线和资源约束取关键路径，不重复累计重叠区间
```

对于单任务服务时间分别为 `t_i` 的理想独立流水阶段，稳态吞吐上限为 `1 / max(t_i)`；`K` 个任务的理想总时间约为 `sum(t_i) + (K - 1) × max(t_i)`。该估计假定各阶段独占资源、缓冲充分且无额外争用。批处理等待可能改善吞吐但增加单请求延迟，需单独测量。

## 串行流程的改写入口

| 现有结构 | 候选改写 | 工作量与依赖链的典型变化 | 必须证明或计入 |
|---|---|---|---|
| 每个位置重扫前缀 | 复用前缀状态；大规模时分层 scan | 重复扫描 `W=Θ(n²)` 可先降为 `Θ(n)`；工作有效的并行 scan 可达 `D=Θ(log n)` | 运算可结合性、分块偏移、尾部、溢出及浮点顺序 |
| 单条累加或归约链 | 局部归约 + 树形合并 | `W=Θ(n)`，理想 `D` 由 `Θ(n)` 降至 `Θ(log n)` | 合并次序及精度契约；确定性；通信成本 |
| 串行筛选后逐项写出 | predicate + scan + scatter | 在适当扫描算法下 `W=Θ(n)`、`D=Θ(log n)` | 稳定顺序、输出位置唯一性、额外缓冲与多遍访存 |
| 高争用共享计数或原子更新 | 私有计数、分片、分桶后合并 | 用局部工作减少竞争链；总工作与空间可能增加 | 热点分布、私有空间、合并成本及计数溢出 |
| 可组合的状态递推 | 块内处理 + 状态变换组合扫描 | 仅在存在高效可结合摘要时缩短跨块依赖 | 组合方向、摘要大小、数值稳定性；一般递推不能直接并行 |
| 按来源固定分配或整批等待 | 就绪任务队列、分块分配、工作窃取 | 减少不均衡及人为等待，未必降低算法工作量 | 队列成本、所有权、发布顺序、重复消费与进度保证 |
| 拷贝后整批计算，再整批发送 | 分块双缓冲和异步流水 | 通过重叠缩短关键路径 | 数据依赖、缓冲回收、引擎能力及带宽争用 |

`Θ(log n)` 依赖理想并行算法及足够资源；映射到有限 `P` 后重新计入块内串行工作与调度。浮点加法不严格满足结合律，树形改写不能默认保持逐位结果。

## 执行方式与资源复用

| 执行方式 | 适用条件 | 验证要点 |
|---|---|---|
| 多进程 | 相对独立、工作足够大的 CPU 任务，或需要避开特定解释器锁 | 进程池复用、启动方式、IPC、数据复制、共享内存生命周期、NUMA 和结果合并 |
| 多线程 | 共享数据，任务可独立或有可控同步；运行时允许真实并行 | 持久线程池、锁与原子热点、伪共享、线程亲和性、嵌套库线程池和超额订阅 |
| SIMD | 连续或可有效重排的数据、可向量化运算 | 实际编译结果、对齐、别名、尾部掩码、gather/scatter 成本和数据布局 |
| SIMT | 设备支持相应执行模型，存在足量细粒度任务 | lane/block/核映射、分支发散、访存合并、寄存器与片上空间、驻留限制、跨组同步 |
| 异步流水 | 独立任务或分块间允许阶段重叠 | 真正完成时刻、队列深度、背压、缓冲复用；异步不保证硬件同时执行 |

Python 中核实实现、构建方式和当前 GIL 状态。常规 CPython 的 CPU 字节码线程受 GIL 限制；释放 GIL 的本地计算及自由线程构建需要分别判断，不能断言所有 Python 线程都无法并行。[Python 线程文档](https://docs.python.org/3/library/threading.html)

对多进程方案把大数据传递及池启动成本计入端到端结果；共享内存和批量任务仅是候选，收益需要实测。[Python 多进程文档](https://docs.python.org/3/library/multiprocessing.html)

在 Ascend 等 NPU 上先核实芯片、CANN、编译模式及目标内核支持的执行模型、同步与片上存储约束。不能把 CUDA warp、隐式同步或内存语义直接套用到 AIV/AIC/SIMT；缺少依据时查对应版本官方文档或现有验证过的实现。

- [NERSC Roofline 模型](https://docs.nersc.gov/tools/performance/roofline/)：用于区分计算与不同内存层级的带宽约束；不以模型替代实测。

涉及工具参数或设备能力时查阅与目标版本匹配的一手文档。此文件给出分析方法，不固定任何芯片参数。
