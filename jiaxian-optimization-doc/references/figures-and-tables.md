# 图表规范

## 1. 让视觉承担解释

完整优化报告优先准备下列图表，而不是将所有信息压成一张大图。已有材料少时缩减，不补造数据。

| 位置 | 图/表 | 要回答的问题 |
|---|---|---|
| 背景 | 场景差异表、基线配置表 | 为什么常规方案在这里不够用？ |
| 瓶颈与上限 | 阶段耗时条形图、关键路径图、模型参数表 | 时间去哪了，最多能省多少？ |
| 软件设计 | 部署/模块图、流程图、时序图、接口表 | 谁负责、数据怎么走、何时同步？ |
| 每项优化 | 前后机制图、布局/流水示意、消融表 | 具体改变什么，为何有效，付出什么？ |
| 验证 | 精度/质量曲线、延迟分布、内存时间线 | 提速是否破坏质量，瓶颈是否转移？ |
| 最终效果 | 阶段结果表、耗时与加速比双联图 | 从初始到最终提升多少，还有多少空间？ |

每张图配“结论式标题 + 配置/口径 + 来源 + 阅读结论”。概念图注明“设计示意”，理论曲线注明“估计”，测量图注明统计量及范围。颜色与线型共同区分系列，打印灰度时仍可辨认。

## 2. 架构图与时序图

- 部署图用边界框区分主机、进程、设备与通信域，注明实例数量；不要把“逻辑模块”和“每卡一个进程”画成同一层。
- 流程图在边上标数据对象、操作和条件；标出关键 layout、队列、Buffer、状态转移、资源上限与完成判据。
- 时序图使用具体参与者，注明异步发起、完成事件、等待、回压、失败/中断与资源释放。只画有证据或明确设计意图的并行；标注版本交接和 Buffer 可复用时间。
- 新旧对比使用同名对象与相同输入，用标注解释新增/删除路径。引用图中步骤号与正文中的优化编号。
- 中小型图用 Mermaid；复杂拓扑、可发表图和精细时轴可用 SVG、draw.io 或标准绘图库。交付可编辑图源与渲染结果；渲染检查标签、箭头、公式和裁切。
- 一张图无法在正常阅读倍率看清时，拆为总览和局部，不缩成不可读的全系统截图。Profiler 截图保留单位、区间与图例，裁出相关区域并解释观察到的变化。

## 3. 最终性能图的数据契约

配套脚本读 UTF-8 CSV，每行表示一个**累计阶段**的同一统计量，首行为基线：

| 字段 | 含义 |
|---|---|
| `stage_id` | 唯一阶段编号，例如 `B0`、`O1`、`O2` |
| `stage` | 中文显示名，例如“初始基线”“加布局优化” |
| `time_ms` | 相同计时边界的正有限毫秒数 |
| `config_id` | 可比条件组，覆盖硬件、输入、计时及统计口径；所有行相同 |
| `evidence` | `measured`、`reported` 或 `estimated`；一张图只接受一种 |
| `source` | 原始实验/报告路径、页码或数据记录定位；不能为空 |

优化开关的累积变化通过 `stage` 和正文阶段表说明，不因此改变 `config_id`。设备数、工作量或计时定义变化必须拆组。`source` 是来源声明，脚本不验证文件是否真实或结论是否有依据。

命令行 `--statistic` 填真实统计口径。没有样本数时写“原文阶段耗时，样本数未给出”，不能为了通过检查填默认 n。

输出：

- `optimization.svg`：上图耗时，下图相对首阶段的累计加速比；显示证据类别，估计图额外加虚线。
- `metrics.csv`：保留输入，新增相对前一阶段与累计节省时间、累计耗时降幅、阶段/累计加速比。

脚本将拒绝负数、零、NaN/Inf、缺失来源、重复编号、不同可比组或混合证据状态。混合资料应拆图或使用有明确分组的自定义图，不能修改状态标签以绕过限制。

缺失数据不传入脚本强行作图：保留采集表的待测行；只有初始与最终值时画两个点。没有绝对耗时时，可以展示明确分母的原文相对指标，但不能逆推出未知绝对时间。

## 4. 图形选择与复算

- 耗时图优先从零起轴；累计加速比给 1.0 倍基线。默认两个面板共用阶段轴，避免双纵轴产生的视觉夸大。
- 数据点多时拆分阶段或增加横向空间，不能为了保持一页而缩小到不可读字号。
- 瀑布图只用于同一链条上可加的时间差；与阶段结果表闭合。不把局部百分比、独立消融或不同配置混成瀑布。
- 堆叠图只用于可加的串行区间，重叠活动用泳道时轴；不将 CPU 时间与 NPU 时间直接堆到 E2E 总时间上。
- 误差条必须从重复实验计算，不能装饰性添加。图注明统计量、单位、样本量、基线和工作量。
- 交付前复算至少首末加速比、耗时降幅和关键边际收益；检查负收益是否如实保留、图表与正文是否来自相同数据版本。
