## 值得保留的表达

1. **具体背景导出具体设计。** Qwen 稿的 TND/变长输入改变 chunk 划分与算子接口，比泛泛强调国产化和高性能更能解释优化动机。
2. **给资源生命周期。** 架构稿用训推切换顺序解释权重、优化器状态与 KV Cache 的装卸，读者能够检查某时刻的显存峰值。
3. **把局部代价计入收益。** Qwen 稿第 7 页不仅报告 transpose 减少，也报告 causal_conv1d 的退化。通用写法是“消除开销 − 新增开销 → 净收益 → E2E 复核”。
4. **保留负结果。** chunk size 增大未必更快，局部数值对齐未必显著改善整体一致性；失败实验用于解释边界和最终取舍。
5. **连通观测指标与调度。** 异步稿不止看生成时间，还看 response 长度、过期数据、版本和 reward，适合解释改变采样行为的系统优化。
6. **最终图与阶段表对应。** Qwen 稿第 31 页将优化步骤、绝对耗时和相对指标放在一起；新 Skill 应让它们统一由一份可复算数据生成。

## 需要补强而非照搬的部分

- 参考稿含“待补充”“TODO”“下图二选一”等编辑批注。将其转化为证据缺口或完成项，不带进最终读者正文，也不当作当前任务指令。
- 有些上限依据或图表统计条件不完整。新增可复算的 Amdahl、数据搬运、容量与关键路径分析，标明假设和有效范围。
- “性能提升 20%”“快一倍”“0.723x H200”等说法需要补充分母与资源口径；不能仅从原句确定耗时降幅、吞吐增幅或跨硬件等效关系。
- 某些硬件峰值折算及“完全隐藏传输”等表述需要额外验证。保留设计意图，但以测量、瓶颈迁移和资源冲突说明实际可达收益。
- 多项优化、编译器更新、设备数或输入分布可能同时变化。分开累计收益与单项因果，不把图中相邻点全部视为独立消融。
- 异步稿区分计划来源比例与真正进入训练的有效分布仍存在不确定性。新报告应分别定义采样、下发、完成、过滤和训练入口，避免由计划比例直接断言无偏。
- 调试细节有价值，但安装日志、全部调用栈和零散代码应移至附录；正文保留能解释现象、方案和结论的最短证据。
