# 军旅术语映射

按结构相似性选择词，不要求所有事项都有军事对应。以下表达用于组织管理和研发汇报，不能代替具体业务事实。示例句中的对象和行动均为示意，按实际材料替换。

## 目标与范围

| 研发事项 | 军旅抽象 | 管理判断或动作 | 汇报句式 |
|---|---|---|---|
| 阶段内最重要的业务目标 | 主攻方向 | 集中优先级和资源 | 本阶段以端到端时延为主攻方向，围绕这一目标安排优化。 |
| 一项能力带动多个产品 | 制高点 | 识别共用能力的价值 | 统一编译能力是技术制高点，突破后可支撑多条产品线。 |
| 下游必须经过的依赖 | 关键隘口 | 优先解除阻塞 | 该接口是交付链路的关键隘口，打通后才能推进联合验证。 |
| 任务过多、单项投入不足 | 战线过长、兵力分散 | 收缩范围并明确取舍 | 当前战线过长，建议暂停次要任务，保障主攻投入。 |
| 需求持续增加 | 作战目标扩大 | 重新匹配范围、资源和期限 | 新增目标扩大了作战范围，需要同步调整交付边界。 |
| 技术路线选择 | 正面突破、迂回路线 | 比较时间、成本和后续负担 | 建议先经兼容层迂回完成交付，再评估底层替换。 |
| 分阶段交付 | 阶段作战目标 | 将大目标拆成可验收结果 | 第一阶段打通链路，第二阶段验证规模，第三阶段完善保障。 |
| 停止低收益方向 | 主动转进、收缩战线 | 明确退出及业务影响 | 建议停止该方向投入，将骨干转到主攻任务；原定能力将延期。 |
| 多团队集中突破同一关键目标 | 会战 | 统一目标、编组和验收 | 本轮会战围绕规模交付组织，统一各团队的阶段目标。 |
| 维护已有可用能力和客户体验 | 阵地保卫战 | 明确必须守住的指标 | 当前重点是守住稳定性阵地，先处理影响现网的缺陷。 |

## 侦察与推进

| 研发事项 | 军旅抽象 | 管理判断或动作 | 汇报句式 |
|---|---|---|---|
| 需求调研、现网摸底 | 战场侦察、地形勘察 | 补齐事实再选择方案 | 现网负载侦察不足，需要补齐数据后确定优化路线。 |
| 原型和小规模实验 | 火力侦察、试探性进攻 | 低成本验证关键假设 | 先做一轮火力侦察，验证路线可行性，再决定投入规模。 |
| 架构与依赖分析 | 作战地图、地形图 | 明确通路与阻塞点 | 先画清依赖地图，识别哪些环节限制整体推进。 |
| 已定位的技术难题 | 攻坚目标 | 收敛问题与突破标准 | 攻坚目标已收敛到同步开销，需要用端到端对照确认收益。 |
| 核心链路不通、外围功能增多 | 主通道未打通 | 调整建设顺序 | 外围能力已具备，下一阶段集中打通主通道。 |
| 减少串行依赖 | 开辟多条通路 | 解耦接口、增加有效并行 | 通过接口解耦开辟多条通路，让开发和验证可以并行。 |
| 首个端到端可用场景 | 建立桥头堡 | 先验证闭环再扩展 | 先在典型场景建立桥头堡，再逐步扩大覆盖范围。 |
| 优化后瓶颈变化 | 主要阻力转移 | 根据新证据调整重点 | 计算侧已有改善，主要阻力转移到通信链路。 |
| 一次成功的方法重复应用 | 固化战法 | 将方法转成可复用流程 | 将本轮诊断方法固化为战法，减少后续重复摸索。 |
| 监控、日志和性能观测 | 战场感知 | 建立可信的状态信息 | 当前感知链路不完整，需要补齐日志才能判断阻力位置。 |

## 组织与保障

| 研发事项 | 军旅抽象 | 管理判断或动作 | 汇报句式 |
|---|---|---|---|
| 围绕完整业务目标组织的大团队 | 军团、任务编组 | 明确共同目标和责任边界 | 围绕端到端交付组建任务编组，由统一负责人牵引。 |
| 专家支援关键问题 | 集中优势兵力、配属支援 | 明确能力、时长与退出条件 | 建议配属通信专家支援关键路径，完成定位后归建。 |
| 增加针对性技术或验证投入 | 加强炮火 | 指定投入解除的约束 | 建议在兼容性验证方向加强炮火，增加自动化覆盖与专用环境。 |
| 多专业共同完成交付 | 多兵种协同、联合作战 | 统一接口和验收节奏 | 单模块能力已具备，下一阶段需要联合作战完成系统验证。 |
| 各部门节奏和目标不一致 | 各自为战 | 指定共同目标与牵引机制 | 当前各线推进节奏不同，需要统一里程碑与验收条件。 |
| 跨团队接口无人闭环 | 结合部薄弱 | 明确接口责任人 | 主要问题位于平台与产品的结合部，需要指定闭环负责人。 |
| 专家被日常任务全部占用 | 预备队不足 | 保留关键节点支援能力 | 核心专家已满负荷，交付节点缺少可调用的预备队。 |
| 临时任务持续打断主任务 | 主攻兵力被抽离 | 保障阶段内稳定投入 | 主攻人员频繁被抽调，需要固定本阶段任务编组。 |
| 缺算力额度、测试数据或预算 | 弹药不足 | 量化具体资源缺口 | 当前测试弹药不足，具体缺口是压测额度和代表性数据。 |
| 缺环境、设备或资源到位迟缓 | 补给线、后勤保障 | 改善资源到位与使用条件 | 人员已经到位，测试环境补给尚未跟上。 |
| 工具链、自动化、公共平台 | 装备与保障体系 | 减少重复劳动、持续支撑交付 | 升级自动化装备，减少每轮手工操作和环境准备。 |
| 关键能力只有一人掌握 | 缺少梯队 | 培训、结对并分散单点风险 | 关键岗位缺少梯队，需要安排结对交付和能力传承。 |
| 反复切项目和搭环境 | 频繁转场、非作战消耗 | 减少切换与准备成本 | 频繁转场挤占有效投入，建议按阶段固定工作范围。 |

同一份汇报中，优先把“兵力”映射到人员及其可用能力，把“装备”映射到工具、平台和设备，把“弹药”映射到按任务投入或消耗的资源，把“补给线”映射到资源到位和持续保障机制。业务无法自然对应时，直接使用业务词。

## 质量、风险与成果

| 研发事项 | 军旅抽象 | 管理判断或动作 | 汇报句式 |
|---|---|---|---|
| 稳定性、安全与兼容性要求 | 防线、底线阵地 | 明确不可牺牲的验收条件 | 新能力可以分批交付，稳定性防线必须满足既定标准。 |
| 单元、集成与系统测试 | 分层防线、纵深防御 | 覆盖不同类型风险 | 补齐分层防线，减少缺陷穿透到现网。 |
| 小范围发布后扩大覆盖 | 先遣部署 | 先验证再扩展 | 先在小范围部署，达到扩容条件后扩大覆盖。 |
| 回滚、容灾与应急恢复 | 预设退路、应急预案 | 保障异常后的恢复能力 | 发布前演练回撤方案，确认异常时能够恢复业务。 |
| 技术债积累 | 装备欠修、工事欠账 | 识别欠账如何影响交付 | 历史欠账已增加回归成本，需要安排整修窗口。 |
| 演示或单场景成功 | 局部突破 | 明确未覆盖的场景和条件 | 已取得局部突破，规模和稳定性仍待验证。 |
| 补齐回归、文档和维护支持 | 巩固战果 | 防止能力退化并便于推广 | 下一阶段巩固战果，补齐回归和维护文档。 |
| 团队可持续、可重复交付 | 形成建制能力 | 将个人经验转为组织能力 | 将专家经验沉淀到平台和流程，形成可重复交付的建制能力。 |
| 模块改善但整体收益不足 | 战术胜利与战役目标未对齐 | 用业务结果验证局部价值 | 模块指标已有改善，但整体时延目标尚未达成。 |
| 长期平台和基础能力建设 | 持续保障、梯队建设 | 安排稳定投入与阶段验收 | 平台建设需要持续保障，按阶段验证复用和交付收益。 |

## 容易失真的对应

- **增加兵力不等于增加有效战斗力**：说明能力匹配、上手时间和任务可并行程度。
- **投入炮火不等于取得战果**：分别给出投入和产出，检验新增资源是否命中主要障碍。
- **拿下阵地不等于守住阵地**：首次实现与长期稳定分别验收。
- **试探未果不等于执行失职**：允许技术探索排除不可行路线，说明获得的认识和下一步选择。
- **转进不等于没有损失**：保留已投入成本、延期目标和客户影响。
- **会战不等于常态管理**：限定适用目标、持续时间与结束条件。
