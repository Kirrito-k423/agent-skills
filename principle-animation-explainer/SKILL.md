# 原理动画解释

把一句复杂的“它是如何工作的”拆成一条能被读者操作、暂停、点选和核算的数据旅程。直接制作可运行的页面；不要只交付静态流程图或动画构想。

## 先确定解释对象

1. 写出读者在看完后应该回答的 2 至 4 个具体问题，例如“输入从哪里来”“为什么会复制”“何时回到原槽位”。
2. 区分**原理模型**、**某份源码的真实语义**和**实机时间线**。原理模型中的人为示例、简化函数和载荷估算必须就近标明；不要把动画粒子的位置解释成远端完成信号。
3. 对事实性机制先读用户给的材料和必要的一手来源；固定源码、论文或文档版本。记录来源能支持什么，尚不能支持什么。涉及专有实现时优先阅读其真实代码，不从名称猜同步或网络行为。
4. 如果用户给出网站参考，借鉴其交互结构与阅读节奏，自己设计图、文案和样式；不要复制受版权保护的图文或页面代码。

## 建立唯一的计算模型

先在页面之外列出对象账本：对象 ID、所有者、输入值或形状、状态、目的地、变换、返回位置。用一条具体记录走完整个过程，再补齐总体视图。

- 令每个可见数字从同一个确定性模型计算出来，动画坐标、线路、详情卡、计数和公式共享它。参数变化后重新计算，禁止只换标题或局部数字。
- 明确区分对象编号、数据值、字节量、权重与状态；零、未知、未写入和未完成使用不同表示。
- 为每个阶段列出读集合、写集合、移动对象与状态变化。保留可核对的不变量，例如副本总数、输入输出数量、权重和、来源与返回槽位的对应关系。
- 选一个有本地和跨节点路径、有负载不均、可手算的小例子用于验算；再选与目标场景同量级的完整参数规模作为页面演示。缩略图必须显示聚合规则，并允许下钻到真实对象数量，不能把小例子的几个图标冒充整个负载。
- 明确每层的总量、张量形状、显示窗口、聚合比例与字节假设。例如有 8192 条任务时，画布可以按 rank 组聚合，详情仍能访问单个 rank 的完整任务清单；每条流带宽度按模型中的任务数计算。
- 用伪数据或教学函数时明确标记；如果真实数值不可知，就显示“未知”，不要编造。

MoE Dispatch/Combine 的一个可复用小例子见 [MoE 示例与验算](references/moe-dispatch-combine.md)。

## 把模型变成分段故事

通常安排 3 至 7 个可跳转阶段。每段只回答一个问题，标题用动词或可观察结果表达。示例顺序为：输入与路由 → 数据发出 → 处理 → 返回 → 合成与顺序恢复。

默认视图优先使用可平移、缩放的画布。**首屏只保留标题、必要控制、图形组件和从模型计算的少量计数**。不要在画布外堆导言、原理长文、图例卡片或多个解释面板；控件附近也不要附加常驻说明段落。让读者先看见完整对象关系，再自主选择深读位置。

页面至少提供：

1. 一眼能扫过完整机制的总览画布；节点、子模块、对象群和主要数据流同时可见，画布可平移、缩放并一键适配。
2. 阶段导航、播放／暂停、前后步和可拖动进度；任意阶段可重复进入。默认总览不自动弹出详情。
3. **点击或键盘选中子模块后才展开**该模块的原理文字与详细可视化；详情内部再按小节逐级展开，关闭后回到保留上下文的主画布。文字每次只解释当前操作和当前数据。
4. 详情将聚合量拆成实际任务、token、专家、rank、向量维度、原槽位等可检索子元素；给出完整数量与分页或窗口，而不是只展示几个象征性图标。
5. 少量真正影响模型的参数与对照场景。参数切换后，计数、流带宽度、热力图、任务清单、公式值和动画同步改变。
6. 来源、教学假设及限制放入按需打开的独立详情；不挤占首屏。

动画应显示**因果**：谁选择、谁复制、谁处理、谁回传、谁合并。按机制组合至少几种互补的视觉语法，例如随任务数变化的流带、逐格改变的矩阵或热力图、任务清单逐条显露、专家负载柱、向量数值插值、加权贡献与原槽位回填。线上的移动亮点只能作辅助手段，不能成为唯一动画。播放暂停后，冻结画面仍须表达当前阶段、数量与状态。公式应在相应子模块中与具体数字并列，且与计算模型一致。

## 实现与验收

- 优先沿用目标项目技术栈。无需服务端的教学站点可用静态 HTML、CSS 和 JavaScript；避免引入大模型下载或与原理无关的依赖。
- 动画由阶段和进度驱动，允许暂停、拖动和回退；不要让多套定时器分别驱动图与数值。更换参数时重建模型并更新所有派生视图。
- 提供键盘操作、清楚的控件标签、颜色之外的状态文字，以及 `prefers-reduced-motion` 回退。窄屏可横向滚动复杂图，但不能把字压到不可读。
- 先以脚本或手算检查模型不变量，再实际打开页面，操作至少一遍播放、暂停、跳步、参数切换、对象选择和进度拖动；从总览点击进入每种关键详情，核对实际行列数与计数。截图检查首屏是否被文字挤占、是否仅有稀疏连线或单个移动点，以及弹层和手机宽度的遮挡与溢出。检查浏览器错误和公式与模型的一致性。
- 区分“本地页面可用”“构建通过”“公网已部署且可访问”。只有实际从公网地址读到目标页面并操作关键交互后，才报告公网完成。
- 交付页面入口、示例参数、来源、教学假设、未验证边界和实际测试结果。用户要求发布时沿用项目的站点流程；对博客正文遵守该仓库的审核与公开规则。

## 遇到具体源码时

如果页面声称对应某函数或某个提交，读取输入生产者、目标函数、输出消费者及同步路径，给出准确文件与提交。复杂多 rank 的逐元素源码动画优先结合 `$data-flow-animation`；本 Skill 负责读者问题、交互故事和原理边界，不能用教学模型冒充源码逐行执行。
