# 原理动画解释

把一句复杂的“它是如何工作的”拆成一条能被读者播放、暂停、拖动和核算的数据旅程。直接制作可运行页面；不要只交付静态流程图、参数面板或动画构想。

## 先确定解释对象

1. 写出读者看完后应该回答的 2 至 4 个具体问题，例如“输入从哪里来”“为什么会复制”“怎样加权”“何时回到原槽位”。每个控件和画面都必须服务于这些问题。
2. 区分**原理模型**、**某份源码的真实语义**和**实机时间线**。人为示例、简化函数和载荷估算必须就近标明；不要把动画粒子的位置解释成远端完成信号。
3. 对事实性机制先读用户材料和必要的一手来源，固定源码、论文或文档版本。记录来源能支持什么、不能支持什么。涉及专有实现时优先阅读真实代码，不从名称猜同步或网络行为。
4. 如果用户给出网站参考，分别调查其配色、视觉语法、时间状态和阅读节奏，借鉴适合当前问题的部分；不要复制受版权保护的图文或页面代码，也不要把参考站的局限一起照搬。

## 建立唯一且足够小的计算模型

先在页面之外列出对象账本：对象 ID、所有者、输入值或形状、状态、目的地、变换、返回位置。用一条具体记录走完整个过程，再补齐总体视图。

- **默认选择能覆盖完整因果链的最小例子**，而不是先选真实部署规模。例子应让读者能手算，并至少覆盖一个关键分支或边界；例如一条本地路径和一条跨节点路径。
- 固定一条贯穿全页的主记录，让它的输入、路由、变换、权重和输出在所有阶段保持同一身份。读者应能用它回答“这一个对象后来怎样了”。
- 小例子的总体计数仍须来自完整模型。若例子是 8 个 token、Top-2，就建立全部 16 条任务记录；可以只高亮其中两条，但不能把高亮图标冒充全局总量。
- 令每个可见数字从同一个确定性模型计算出来，动画坐标、线路、任务账本、计数和公式共享它。禁止只换标题或局部数字。
- 明确区分对象编号、数据值、字节量、权重与状态；零、未知、未写入和未完成使用不同表示。保留可核对的不变量，例如任务总数、输入输出数量、权重和、来源与返回槽位对应关系。
- 为每个阶段列出读集合、写集合、移动对象与状态变化。用伪数据或教学函数时明确标记；真实数值不可知就显示“未知”，不要编造。
- **规模是按需增加的解释维度，不是默认配置项。**只有读者问题是负载不均、全量 shape、通信量或聚合比例时，才加入目标量级、完整矩阵、分页或下钻；此时明确显示窗口、聚合规则和字节假设，不能让大图取代核心因果链。

MoE Dispatch/Combine 的一个可复用手算例子见 [MoE 示例与验算](references/moe-dispatch-combine.md)。

## 用一条时间轴串起故事

通常安排 3 至 7 个可跳转阶段，每段只回答一个问题，标题用动词或可观察结果表达。示例顺序为：输入与路由 → 数据发出 → 处理 → 返回 → 合成与顺序恢复。

默认采用**内联原理图 + 当前步骤就地解释**，让读者不用打开弹层就能看懂核心机制。首屏只保留标题、固定例子的必要说明、主图、少量控制和当前解释；不要先堆导言、模型配置、图例卡片或多个详情面板。

核心控制预算通常是：

1. 播放／暂停与重播。
2. 一条可拖动、可回退的时间轴，以及可点击的阶段导航。
3. 必要时提供键盘步进；所有操作都暂停或继续同一条时间线。

速度、预设规模、Top-k、热点场景、rank/token/维度窗口、缩放平移和独立详情播放都不是默认必需项。每个额外交互都要通过教学必要性测试：

- 去掉它后，核心问题是否将无法回答？若答案是否定的，就删除、固定或放到按需详情。
- 它是在改变解释模型，还是只改变观察方式？不要把观察窗口伪装成模型参数，也不要同时开放多个会互相稀释注意力的变量。
- 对照是否只改变一个关键因素，并能共享当前时间？否则优先拆成两个连续例子，而不是加一组配置。
- 能否通过直接点选图中对象代替下拉框？能直接选择时，不再添加平行的表单控制。

当前步骤的标题、短解释和公式应与高亮对象同步更新，并放在图旁或图内可见位置。公式旁列出本例的真实数字。来源、完整账本、教学假设和限制可放入按需展开的详情，但**核心原理不能只藏在弹层里**；需要弹层时也不要再创建第二套独立播放时钟。

## 让视觉表达因果，而非装饰

- 使用中性色承载纸张、文字、空槽和结构线，默认一个主强调色；只有需要区分第二条路径或对照状态时，才增加一个辅助强调色。颜色身份在全过程中保持稳定。
- 参考色可以用于线条和图形身份，但不能未经验证就作为小号文字色。测量正文、公式、标签与实底上文字的对比度；需要时使用同色相的深色文字／填充变体，不以“还原来源”为由牺牲可读性。
- 不要只靠颜色。用标签、形状、实线／虚线、填充／空心等共同表达本地与跨节点、发送与返回、等待与完成。
- 动画应显示**因果**：谁选择、谁复制、谁处理、谁回传、谁合并。移动粒子必须与对象状态、数值或槽位变化结合，不能成为唯一动画。
- 暂停后，冻结画面仍须表达当前阶段、对象身份、数量与状态。不要通过插值数字制造并不存在的中间机制；可以移动对象或逐步显露已经由模型算出的结果。
- 对小型原理图优先使用原生 SVG 和确定性数据，不必引入视频、大型动画库或画布缩放。图复杂到需要总览与下钻时，再增加平移缩放、热力图、矩阵和窗口。
- [Cold Starts 参考页](https://www.sahilmahendrakar.com/writings/cold-starts)的可借鉴点是：白底与灰色结构线、少量蓝／橙强调、原生 SVG、图内时间轴、播放与 scrub 共用 `draw(t)`、屏外不更新及 reduced-motion 静帧。其正文并不随动画联动，密集固定画布也不宜直接照搬到手机。

## 实现与验收

- 优先沿用目标项目技术栈。无需服务端的教学站点可用静态 HTML、CSS 和 JavaScript；避免引入与原理无关的依赖。
- 用 `phaseAt(time)` 与单一 `render(time)` 驱动对象位置、填充、文字、公式、计数和游标。播放、拖动、阶段跳转都调用同一入口；限制帧时间差，页面隐藏时暂停，禁止多套定时器分别驱动主图和详情。
- 默认不自动播放，或在进入视口后采用不打扰阅读的单一播放策略。尊重 `prefers-reduced-motion`：初始提供可理解的静帧，用户主动操作时允许逐步查看。
- 提供清楚的控件标签、键盘操作、阶段 `aria-current`、必要的文字状态，以及颜色之外的区分。窄屏应重排图文或允许图内横向滚动，不能把整幅密集图缩到不可读，也不能造成页面级横向溢出。
- 先以脚本或手算检查模型不变量，再实际打开页面，操作播放、暂停、重播、阶段跳转、进度拖动和键盘步进。对同一时间分别通过播放与 seek 到达，核对图文状态一致；逐个阶段核对公式、数字、对象身份和总数。
- 检查首屏是否存在不必要的模型配置，核心解释是否无需弹层即可阅读，控件是否都作用于同一时钟。检查浏览器错误、窄屏遮挡与页面溢出，并用截图审阅视觉层级；不能只以构建成功代替交互验收。
- 区分“本地页面可用”“构建通过”“公网已部署且可访问”。只有实际从公网地址读到目标页面并操作关键交互后，才报告公网完成。
- 交付页面入口、固定例子、来源、教学假设、未验证边界和实际测试结果。用户要求发布时沿用项目站点流程；对博客正文遵守仓库的审核与公开规则。

## 遇到具体源码时

如果页面声称对应某函数或某个提交，读取输入生产者、目标函数、输出消费者及同步路径，给出准确文件与提交。复杂多 rank 的逐元素源码动画优先结合 `$data-flow-animation`；本 Skill 负责读者问题、交互故事和原理边界，不能用教学模型冒充源码逐行执行。
