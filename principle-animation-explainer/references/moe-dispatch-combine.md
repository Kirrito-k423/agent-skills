# MoE Dispatch/Combine 教学例子

这是一份**原理模型**，用于制作和验算交互页面，不表示任何特定通信库的内存布局或硬件时序。

## 对象与配置

- 4 个 rank：R0 至 R3；每个 rank 拥有 2 个输入 token 与 2 个专家。
- 8 个专家：E0 至 E7；`owner(Ee) = floor(e / 2)`。
- 每个 token 选择 Top-1 或 Top-2 专家。Top-2 产生两份逻辑专家任务，两个权重之和为 1。
- 每个 token 保留 `(原 rank, 原槽位)`，以便 Combine 返回并恢复顺序。
- 展示的 `x[0]` 只是 token 向量首元素的教学值。为了手算，设 `Fₑ(x[0]) = x[0] + 4(e+1)`；真实专家网络不是这个函数。

## 一条记录的验算

令 `R0:T0` 的 `x[0] = 12`，路由到 E0 和 E3，权重分别是 0.7 和 0.3。

1. 路由生成两条任务：E0 在 R0，本地；E3 在 R1，跨 rank。
2. Dispatch 将两份逻辑副本交给对应专家，保留来源 `R0:T0`。
3. 教学专家结果为 `F₀(12) = 16` 和 `F₃(12) = 28`。
4. Combine 将两份结果返回 R0 的 T0 槽位；`y[0] = 0.7×16 + 0.3×28 = 19.6`。
5. 改为 Top-1 时，只有 E0 一份任务，示例权重为 1，`y[0] = 16`。

## 页面必须守住的不变量

- 总专家任务数等于 `token 数 × Top-k`；8 个 token 的 Top-2 有 16 份，Top-1 有 8 份。
- 各专家接收计数之和等于总任务数。
- “跨 rank”仅在 `原 rank != 专家 owner` 时成立；本地任务仍属于 Dispatch 的逻辑路由。
- 每个 token 最终恰好写回一个原槽位；合成只使用该 token 选中的专家结果。
- 对一个 Top-2 token，两条教学权重之和为 1；不能把复制数误当 token 数。
- 若估算每份 token 向量为 H=4096、BF16，则载荷是 `4096×2=8192` 字节。单向跨 rank 载荷只可按跨 rank 任务数乘以 8192；不要把它叫作链路实测流量，因为还可能有索引、权重、对齐、协议与重传等开销。

## 图与文案的边界

把路由、Dispatch、专家计算、Combine、恢复顺序作为教学阶段。粒子走到目标只说明演示进度，不说明网络已收到、远端已执行或全部 rank 已同步。真实运行可以有异步提交、流水重叠和不同的缓冲布局；这些需由指定实现的源码或实机证据另行支持。

进一步核对通用接口时阅读 [DeepEP 官方仓库](https://github.com/deepseek-ai/DeepEP)。交互组织可参考 [Transformer Explainer](https://poloclub.github.io/transformer-explainer/)；只借鉴操作模式，不复用它的图文代码。
