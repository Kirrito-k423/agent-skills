# 快速学习闭环

把 AI 用来组织知识、发现盲区、提供反馈。把学习是否完成落实到用户能独立解释、操作和迁移的证据上。

方法来源与改编边界见 [视频方法与来源](references/video-method.md)。需要组织简报、课程或接续学习时，按需读取 [学习记录模板](references/session-templates.md)，不要一次输出全部空模板。

## 开始前：对齐要学会的事

1. 从上下文提取**主题、用途、已有基础、可用时间、验收任务**。已知信息不要重复询问。
2. 没有主题时先问主题；用途或时间会明显改变路线时，最多用三个简短问题补齐。可以先做不依赖答案的资料核查。
3. 把“了解某领域”改成可观察目标，例如“独立画出数据流并解释两种失败情况”。用户未确定目标时，给出一个可修改的建议，标为暂定。
4. 时间未知时先交付一轮入门框架与第一个练习，不擅自制定长期承诺。将能力状态记为“未测”，用一道短题或已有作品检查基础。
5. 尊重所请求的范围：只要学习计划，就交付计划；只要测验，就从测验开始；已有学习记录，就从最近的未完成项继续。

**首次带学交付：** 简要说明目标与路线，给出理解第一课必需的框架，然后安排一个用户现在就能做的动作。不要先堆满十步的长报告。

## 阶段一：建立领域框架

### 1. 用五个视角提出好问题

默认在当前会话内模拟以下视角，并明确它们是分析角度，不是真实专家意见或独立研究结论：

| 视角 | 重点问题 |
| --- | --- |
| 实践者 | 具体解决什么问题？最小可行操作是什么？ |
| 学者 | 核心概念、机制、前提和证据分别是什么？ |
| 怀疑者 | 何时失败？有哪些反例、误解和遗漏？ |
| 经济学家 | 学习与应用成本是什么？替代方案和机会成本是什么？ |
| 历史学家 | 它为什么出现？哪些变化塑造了今天的方案？ |

按主题替换不合适的角色，但保留用途、机制、反例、成本和演变这几类问题。每个视角只提出最相关的问题，围绕关键问题查资料，不为角色数制造重复内容。

优先使用用户材料、官方文档、原始论文和可核查案例。涉及具体外部资料、易变化的信息或不确定事实时查证，并把引用放在对应判断旁。不能读取原文时标记“未核验”；只有视频简介时，不声称看完视频或取得逐字稿。

### 2. 整理分歧与盲区

用紧凑表格整理：**争议问题 → 不同主张 → 各自前提 → 证据 → 可验证动作**。

- 区分事实冲突、适用条件不同和价值取舍，不把所有差异都称为矛盾。
- 没有真实分歧就记录共识与适用边界，不强行让角色争吵。
- 提出至少一个值得检查的盲区；不要把“几种视角都没提”直接当成新发现。
- 对影响学习路线的争议优先核查，给其余未知项保留标记。

### 3. 压成一页入门简报

让读者迅速找到：主题解决的问题、核心对象及关系、最重要的判断、主要分歧、适用边界，以及接下来要做的一个动作。面临具体选择时再写成决策简报。

先给整体关系，再解释术语；使用一个贯穿的小例子。以单屏至一页的可读长度为目标，不靠缩小文字塞入全部资料。

### 4. 严格审查并修订

从**事实可靠性、概念准确性、推理缺口、反例覆盖、行动可行性**检查简报。指出最关键的缺口，补证据或收窄结论后再继续。

可以模拟严格教师的提问风格，但不得冒充某校教授、声称获得学术背书，或把同一模型的自检称为独立审核。角色数量和一致表态不能提升证据等级。

## 阶段二：聚焦核心并安排练习

### 5. 精选少量资源

默认保留最多五个互补资源，按基础到应用排序。为每项写出链接、解决的问题、先修要求、需要读的具体部分、预计用时和一个练习。

实际读取后再推荐，区分实测用时与估计用时。无需凑满五个，不虚构已经筛选过几百项。来源无法访问时，交代限制并使用已核验替代材料。

### 6. 画出五级能力地图

沿以下方向为当前主题定制可观察任务；把它作为本次学习的工作量表，不作为标准化能力认证：

| 等级 | 可观察的能力 |
| --- | --- |
| 一级：辨认 | 识别核心对象、术语和它解决的问题 |
| 二级：解释 | 用自己的话说明机制、关系和必要前提 |
| 三级：应用 | 独立完成一个代表性任务并检查结果 |
| 四级：诊断 | 解释失败案例，比较方案及其边界 |
| 五级：迁移 | 在新条件下调整方案，并用证据说明取舍 |

分别记录已展示的能力、证据和待测项。用当前最高的、有证据支持的能力描述进度；没有作品或作答时保持“未测”。自述熟练度仅作初始线索，不等于通过测试，也不必从一级重复学习。

### 7. 围绕核心概念设计课程与小项目

选出对目标最有解释力、复用价值或先修价值的少数概念，画清依赖关系。把“20% 核心”理解为取舍方法，不虚构精确比例，也不跳过正确性所需的基础。

每一课包含**要解决的问题、最小讲解、用户练习、验收证据、预计时长**。将至少一个小项目接入课程，预先说明交付物、通过标准和常见失败。

- 短时入门：压缩为框架、关键概念、一个代表性练习和一次检查。
- 多日学习：按可用时间排课，给实践与反馈留出时间；用户需要时可采用一周或十四课结构。
- 按“课次 × 每课用时 + 项目与复习用时”检查总预算，超出时削减范围，不能只缩短标注时间。

AI 可以示范和提供提示，但由 AI 完成的项目不能用来证明用户已经会做。安排一个用户独立完成的变式任务作为检查。

## 阶段三：检验理解并巩固

### 8. 逐题测验，定位最先卡住的地方

1. 先按目标确定判分依据，例如关键机制、正确步骤、适用条件和反例；依据可靠材料判断答案。
2. 从与用户基础匹配的题目开始，**一次出一道，等用户回答后再给反馈和答案**。用户明确要求题库时可批量输出，答案单独放置。
3. 检查推理过程和结果；记录“独立完成、提示后完成、尚未完成”，不给缺失的作答编造分数。
4. 答对后换一个条件检验迁移；答错后指出具体缺口，提供最小提示，再用不同题目检查同一概念。
5. 连续两题受阻时，默认降一级、补例子并缩小任务；用户要求暂停时停止。把挑战控制在有反馈的练习中，不追求挫败或羞辱。

按当前目标判断是否足够，不要求每个人都考到第五级。用户只说“继续”时，优先推进一道练习或修补一个缺口。

### 9. 让用户完成费曼讲解

请用户面向没有背景的人，用自己的话说明“它是什么、为什么这样工作、举一个例子、何时不适用”。检查含糊代词、术语替代解释、推理跳步，以及类比失效处。

针对最关键的漏洞追问，再让用户修改讲解，直到能清楚说明核心机制与边界。听起来通俗只是检查的一部分，仍需核对事实和代表性任务。用户要求示范时可以先演示，但要说明示范不能算作用户通过。

### 10. 压成一页速查表并留下复习入口

收录核心关系、操作步骤、选择条件、常见错误、最小例子和关键来源。标出仍未掌握或未核验之处，删除对当前用途没有帮助的内容。

安排一次稍后不看资料的回忆或变式练习，根据用户实际作答调整复习间隔。若只是交付学习包，给出自测入口并将结果记为“待测”，不要自行宣布掌握或创建定时任务。

## 交付与接续规则

- 按请求交付当前阶段最有用的成果：入门简报、资源与路线、练习反馈或速查表。完整资料包可以覆盖十步，但计划、示例答案和空测试不能冒充学习结果。
- 每轮用一句话记录：**已做什么 → 证据是什么 → 还卡在哪里 → 下一步做什么**。
- 需要跨会话接续时，在用户指定的学习文档中保存目标、当前步骤、练习记录和未解决问题；否则在会话中保留简短交接，不写入全局记忆。
- 不承诺“十倍速”“两小时精通”或固定课数见效。若用户要比较学习效率，先明确相同任务的用时与正确性基线，再比较独立作答、迁移和后续保持情况。
