# 系统 SOP 可视化说明

把系统中「谁在何时做什么、交给谁、凭什么判定完成」整理成可核对的 HTML。先调查现状，再画图；不要把目标架构、示例运行、模拟测试或人工步骤写成已经实现的自动化能力。

## 1. 冻结依据

1. 确定用户要求的仓库和版本。记录 Git 提交或文档版本，以及调查日期；若工作树有未提交变更，说明本次以哪个状态为准。
2. 读取入口、配置、协议、持久化、通道、执行和验证相关代码与文档。对关键动作追到实际函数或接口；文档与代码冲突时标明差异，不用猜测填补。
3. 为每条关键关系记录可点击的本地相对路径或公开来源。把「代码已实现」「文档约定」「外部/人工执行」「规划中」「有实测证据」分开标注。证据缺失写「未验证」。
4. 无法访问某个运行环境时仍可画代码层 SOP，但必须注明它没有通过该环境的端到端验证。

## 2. 建立对象与交接模型

1. 枚举人、AI、进程、持久化状态、消息通道、产物存储、执行环境等参与对象。区分主动对象和被动对象；同类对象在不同机器上有独立状态时分别列出。
2. 对每个对象记录：职责、触发条件、输入、输出、持有的状态、失败或重试边界、直接交接对象、证据与实现状态。先完成对象表，再作图。
3. 找出业务标识、消息类型和状态机：谁创建标识、谁改变状态、何时确认、重复请求如何处理、故障后从哪里恢复。
4. 明确「已提交」「已读回」「已领取」「已实际执行」「产物已校验」「业务验收通过」各自的证据。名称相近时尤其不能合并。

## 3. 绘制完整视角

在同一份 HTML 中依次呈现：

1. **对象组成与边界**：拓扑图或对象关系图，附对象表和图例。标出机器/网段、共享通道、存储和外部执行者。
2. **全局流程图**：从任务准备到最终回执及人工判读，列出主要分支、失败暂停点和恢复入口。箭头写明触发条件或产物，不用无意义的「下一步」。
3. **全局时序图**：按时间顺序显示参与者、事件、读写、确认与轮询。必要时用注释说明异步等待与本地持久化的先后关系。
4. **逐对象流程图**：对象表中的每一个对象都有一张以其职责为中心的流程图，包含入口、关键决策、输出和异常/等待；被动对象显示接收、保存/返回、拒绝等行为。
5. **逐对象时序图**：同样每个对象都有一张以它为主角的时序图，展示它和上下游的消息以及本地状态变化。不要只复制全局时序图；突出该对象何时可观察、何时仍未知。
6. **操作 SOP**：列明操作者在各端的入口、最小操作、预期产物与停止条件。若某步由外部 AI/人工完成，要直说。

按对象清单逐一检查：对象数为 N 时，HTML 至少有 1 张全局流程图、1 张全局时序图、N 张逐对象流程图、N 张逐对象时序图。图中的事件名称、方向、状态与正文保持一致。

## 4. 生成离线 HTML

1. 生成单个可直接通过 `file://` 打开的 UTF-8 HTML；样式、绘图代码和数据内联，不依赖 CDN、在线 Mermaid、远程字体或网络请求。可以使用内联 SVG、HTML/CSS 和少量原生 JavaScript。
2. 顶部提供版本、事实边界和阅读导航；对象卡片可直达对应流程图和时序图。长图在窄屏上可横向滚动，文字应可选择、放大和打印。
3. 用一致的颜色/线型标记自动、人工、外部、未实现与异常路径；不能只靠颜色传达含义。图表同时写文字说明和来源，便于无图阅读及审查。
4. 展示重要分支与不变量，但避免把所有函数调用都堆进图。需要细节时链接源码。对暂未实现的对象视角，只画已知的接口边界与人工操作，并明确缺失的自动链路。
5. 不把 Token、服务器密码、内部地址、真实任务隐私数据或大体积产物写进 HTML；示例内容必须可识别为示例。

## 5. 校验与交付

1. 校验 HTML 可解析、离线无外部依赖、图的数量和对象清单相符、对象 ID 与交互端点均存在、相对源码链接可达；有浏览器时实际打开并检查宽窄屏及打印布局。
2. 对照代码复核关键状态、分支和调用顺序。把未在真实环境验证的部分写入页面和交付说明，不以静态检查冒充运行验收。
3. 给出 HTML 与 Skill 的可点击文件路径、所依据版本、验证结果，以及用户可以从页面找到的最重要 SOP 边界。
