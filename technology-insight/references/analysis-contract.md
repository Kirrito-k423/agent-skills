# 技术洞察决策与证据合同

在开始大规模检索、克隆仓库或运行实验前填写本合同。未知项可以写“待确认”，但必须说明它是否阻塞结论。

## 决策合同

| 字段 | 内容 |
|---|---|
| 主题 | 要分析的新技术或技术方向 |
| 决策 | Adopt / Trial / Assess / Hold / Reject / Coexist，或用户定义的选择 |
| Baseline | 当前方案、主流方案或“不采用”的反事实 |
| 候选 | 纳入横向比较的方案及版本 |
| 排除项 | 不分析的相邻技术及原因 |
| 用户与场景 | 谁在什么负载和流程中使用 |
| 成功标准 | 功能、质量、性能、稳定性、成本和时间目标 |
| 硬约束 | 硬件、接口、合规、数据、预算、期限和人才 |
| 时间窗 | 当前、未来 6-12 个月或长期 |
| 决策人 | 谁接受风险并做最终决定 |
| 研究预算 | 时间、算力、API、远程资源和人力上限 |
| 停止条件 | 哪些证据足够决策，哪些未知不值得继续研究 |

## 问题树

只保留能改变决策的问题：

1. **价值问题**：目标场景的真实缺口是什么，不做会怎样？
2. **机制问题**：新技术通过什么物理或软件机制改变结果？
3. **适配问题**：它依赖哪些模型、数据、硬件、接口和组织前提？
4. **效果问题**：在同口径条件下改善了什么，牺牲了什么？
5. **成熟问题**：原型、工程、生态和供应链分别成熟到哪里？
6. **迁移问题**：哪些对象退出、保留、新增，回滚路径是什么？
7. **经济问题**：全生命周期成本和价值如何分布？
8. **风险问题**：什么失效模式会使收益归零或造成不可接受后果？

## 证据等级

| 等级 | 名称 | 示例 | 可以支持 | 不能自动支持 |
|---|---|---|---|---|
| `E0` | 线索 | 新闻、演讲、厂商宣传、社区讨论 | 发现候选和待验证问题 | 实现、效果、成熟度结论 |
| `E1` | 规范/设计 | 标准、官方文档、论文方法、设计提案 | 目标机制、接口和设计意图 | 某版本已实现或在本环境有效 |
| `E2` | 实现 | 固定提交的代码、配置、测试 | 某版本包含特定路径和断言 | 生产稳定、性能优于 Baseline |
| `E3` | 受控验证 | 可复现 Demo、PoC、Benchmark、Profiler | 指定环境中的可运行性和测量结果 | 跨硬件、跨负载或长期生产效果 |
| `E4` | 运行证据 | 披露边界的生产数据、事故、长期稳定性 | 指定生产场景的真实行为 | 其他组织和未来版本的普适结论 |

证据等级表示离目标运行事实的距离，不表示来源“好坏”。论文方法可为高质量 `E1`，但仍不能代替 `E3/E4`。

## 冲击分析合同

对每个候选完成下面的链条：

```text
旧瓶颈或机会
  -> 新机制改变的对象/边界
  -> 直接效果
  -> 被替代、保留和新增的对象
  -> 新瓶颈与新成本
  -> 成立前提与迁移路径
  -> 受益方、受损方和价值重新分配
  -> 可观测验证指标
```

若任一箭头缺少证据，写成待验证假设，不补写确定语气。

## 研究停止规则

满足以下条件时停止继续搜集：

- 已经存在一个满足硬约束且证据足以支持 Trial/Adopt 的方案；
- 新信息不再改变候选集合、排序、退出条件或风险处置；
- 剩余未知对决策影响低，或验证成本高于其信息价值；
- 关键不确定性只能通过超出权限、预算或时间窗的生产试验解决，此时明确升级为条件式结论。
