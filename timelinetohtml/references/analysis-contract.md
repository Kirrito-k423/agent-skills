# 分析数据与计时约定

需要设计模型、三列联动或数值校验时读取本文件。字段名可以调整，但保留身份、证据和单一数据来源关系。

## 建议数据结构

| 对象 | 建议字段 | 约束 |
|---|---|---|
| 来源 | `source_id, kind, revision, path_or_url, clock, unit` | 固定分析版本；运行版本未知要单列。 |
| 阶段 | `phase_id, label, color, start_event, end_event, role` | 颜色不是全局通用的函数名；角色决定实际路径。 |
| 配置 | `case_id, participant, shape, layout, topology_assumption` | 同一编号在不同设备上不是同一参与者。 |
| 依赖边 | `producer, consumer, payload, source_address, target_address, issue_order, ready_event` | 区分本地/跨卡，写出等待的数据或发布标志。 |
| 代码组 | `group_id, phase_id, ranges, operation_count, formula, duration_us, provenance, evidence` | 与其他可相加组互斥；未知时间用 `null`。 |
| 假设 | `parameter_id, value, unit, meaning, basis` | 说明来自独立测量、经验范围还是演示选值。 |
| 观测 | `case_id, phase_id, value_us, provenance, source_id, uncertainty, statistic` | 不从模型覆盖；没有该配置的数据就保留缺失。 |

数值的 `provenance` 采用：

- `measured`：原始测量；记录采集方法、样本范围和统计量。
- `screenshot`：截图估读；记录图像、轴刻度和取值误差。
- `model`：显式公式与假设得到；拟合数据时说明哪些数据用于选参。
- `unknown`：无法取得或不能独立分解；不转成数值零。

源码确认的地址和操作次数是事实，但不能据此把时间标为实测。必要时为计数、模型参数和最终耗时分别记录证据类别。

## 阶段账本示例

下面只示范数据关联，不是固定的七组结构。单位为 μs，代码是明确标记的伪代码。

```json
{
  "phases": [
    {"phase_id": "send", "label": "发送", "color": "#ff7f0e"},
    {"phase_id": "receive", "label": "等输入", "color": "#2ca02c"}
  ],
  "case": {
    "case_id": "目标卡A-核B",
    "participant": {"rank": "A", "core": "B"},
    "groups": [
      {"group_id": "prepare", "phase_id": "send", "code": "prepare()", "code_kind": "伪代码", "duration_us": 1, "provenance": "model", "formula": "P", "evidence": "演示假设"},
      {"group_id": "copies", "phase_id": "send", "code": "send_then_wait()", "code_kind": "伪代码", "duration_us": 6, "provenance": "model", "formula": "24 × 0.25", "evidence": "演示假设"},
      {"group_id": "input_wait", "phase_id": "receive", "code": "wait_input()", "code_kind": "伪代码", "duration_us": null, "provenance": "unknown", "formula": "max(0, A − start)", "evidence": "输入就绪时刻未取得"}
    ],
    "observed": []
  }
}
```

第三列由前两组计算发送为7μs；接收仍是未知，不能把总时间写成7μs。若需要保留已知部分，应显示“已知部分7μs＋未知接收”，而不是完整总时长。

## 不重复计时

1. **父子调用**：若 `outer()` 含 `wait()`，选择父函数整体或子组分解；不能同时累计二者。
2. **异步发起**：`submit()` 返回不等于对端可消费；阶段边界覆盖了什么就报告什么。
3. **到达与等待**：在t=10到达等待点，材料t=6已到，则额外等待为0；材料t=14到，则额外等待为4，而非14。
4. **并发分支**：两分支同时起步、耗时8和13，同步汇合为13；顺序执行才是21。部分重叠应按事件 DAG 推导。
5. **必要检查**：即使额外等待为0，也可能需要一次读取/归约/检查；将其计入固定操作组，不能重复放在等待组和尾部组。
6. **阶段缺失**：未采集或无效打点为未知；源码明确未执行才为0。

若代码耗时是区间，传播上下界或显示可能范围；不要将区间中点隐藏成精确测量。若变量有相关性，逐项上下界相加只代表保守范围，不能称为统计置信区间。

## 统计与坐标

- 对同一组运行，先按运行实例计算阶段和总时长，再计算均值、p50或p99。不能将每组独立的p99相加得到总p99。
- 若比较不同运行集合、不同统计量或不同频率换算，先统一口径；无法统一就单列限制。
- 堆叠条适合互斥的持续时长。重叠事件应采用绝对事件轴或说明重叠关系，不能强行堆成总时长。
- 模型与观测、不同配置之间共用尺度。不得把每条柱子各自归一到100%后声称绝对时长一致。
- `cycle` 到 μs 的换算必须依据该计时器和配置，不默认采用设备主频。
- 截图取值可用“色段像素长度 / 两刻度像素间距 × 两刻度时间差”。记录左右图各自刻度，跨过细网格线时按段外包范围估读，并保留边界误差。

## 最小检查案例

| 输入情况 | 应得到的结果 |
|---|---|
| 输入在等待开始前已到达 | 额外等待为0，固定检查成本保留。 |
| 某个输入晚到，但未超过原有最慢门槛 | 绿/红等相邻等待可以转移，完成门槛不变。 |
| 必需输入晚于所有其他输入 | 整体门槛后移，不能只解释成颜色交换。 |
| 模型反转发送顺序 | 相关输入的排队位置改变；独立的发送条数和原观测不变。 |
| 一个代码组未知 | 对应阶段或完整总时间保持未知，不填0。 |
| 同编号核出现在两个rank | 生成不同参与者，不能合并到同一状态。 |

## HTML 数据边界

把模型计算函数与 DOM 展示分开，并让第三列通过 `group_id` 聚合。公式文本用于解释，真实计算由明确实现的逻辑执行，不将证据文本作为代码求值。

处理源码文本的 HTML 转义；嵌入 JSON 时将 `<` 等危险字符编码，例如编码为 `\u003c`，避免源码中的 `</script>` 提前终止数据容器。配置变化后统一刷新配置说明、代码成本、汇总、差值和反事实提示，避免只有柱长改变而正文保留旧结论。
