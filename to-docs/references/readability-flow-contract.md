# 可读性与行文契约

本契约完整吸收 [`khazix-writer` 第三步“写作”](https://github.com/KKKKhazix/khazix-skills/blob/main/khazix-writer/SKILL.md#%E7%AC%AC%E4%B8%89%E6%AD%A5%E5%86%99%E4%BD%9C) 中可迁移的文章原型、叙事节奏、个人视角、判断姿态、同理心、层层揭示、回环呼应和“活人感”技巧，并适配本仓库偏学术、技术、深入浅出的写作目标。

目标不是扮演卡兹克本人，而是让文章像一个有实践、有判断、愿意承认边界的同行在认真讲一件事。不要复制固定口头禅、粗口、固定结尾、标点禁令或“不使用标题”等个人专属形式；应主动保留素材中真实的第一人称、情绪、犹豫、好恶和口语节奏。

## 质量优先级

事实、来源、保真、隐私和用户明确要求是硬边界。在这些边界内：

```text
读者理解与主线流畅
    > 当前问题所需的技术完整性
    > 标题、列表、表格、公式、图片和检查项的形式覆盖
```

宁可把不服务主线的正确材料移到附录、其他文章或排除说明，也不要让读者在信息堆中寻找重点；删除既有文章内容仍需遵循保全规则。

## 建立读者承诺

起草前明确：

- **目标读者**：已经知道什么，最容易卡在哪里。
- **核心问题**：为什么值得现在读。
- **一句话主线**：读完后能复述的核心判断。
- **阅读结果**：读者能解释、比较、选择或执行什么。
- **文章原型**：调查实验、产品体验、现象解读、工具分享、方法论分享、机制解释、方案比较、会话整理或研究综述。

文章原型只是选择推进方式，不是固定章节模板。

## 选择叙事原型

先判断素材最适合哪种原型，再决定文章怎样推进。原型决定重心，不是固定模板：

- **调查实验型**：作者真的做了一件事。按“具体好奇或困境 → 亲自下场 → 过程与意外 → 层层发现 → 回到日常后的新判断”推进，让读者像跟着一起经历。
- **产品体验型**：作者真的使用了产品。按场景逐项展示实际操作、体感、优缺点和与替代方案的自然比较，不写成参数评测表。
- **现象解读型**：从一个具体反常现象开始，沿“观察 → 好奇 → 表面解释 → 更深追问 → 证据 → 核心洞察 → 更广背景”层层剥开。
- **工具分享型**：从真实需求或个人故事引出工具，展示“挑战 → 想法 → 操作 → 结果”，再说明适用人群、学习成本和失败点。
- **方法论分享型**：先用真实的不确定感卸掉“我来教你”的姿态，再按“观点 → 案例或理论 → 今天能做的动作 → 学习曲线与常见失败”展开。
- **机制解释型**：按“问题现场 → 物理直觉 → 最小例子 → 关键对象 → 运行过程 → 证据与限制”推进。
- **方案比较型**：先逐个讲清方案，再用同一边界比较；不要用一张总表替代发现过程。
- **会话整理型**：按“核心命题 → 为什么会讨论 → 推理如何变化 → 已形成结论 → 行动或开放问题”重组，不复制聊天顺序。

素材可能混合两种原型。选择一个主原型，另一种只承担局部功能，避免叙事姿态来回切换。

## 用问题链组织正文

把素材改写成读者会自然提出的问题链。每一节回答一个主要问题，并产生或引出下一问。判断标准只有一个：后一段是否由前一段自然推出。

允许围绕主线短暂偏出去看一个案例、背景或类比，但离开前先让读者知道为什么要看，回来时用一句短句扣回主线。不要让读者自己承担“这段和全文有什么关系”的拼接工作。

## 开头与结尾

从材料中最具体的事件、矛盾、失败、反常事实、当下场景或好奇心开始。第一句话要让读者自然产生“然后呢”或“为什么会这样”的追问；前两三个段落应让读者知道发生了什么、为什么与自己有关、文章准备解决什么。

没有可信场景时直接提出问题，不编造“有一次”、虚构人物、数据、对话、使用体验或第一人称感受。

结尾优先回到开头的场景、问题、意象或一句话，但此时读者的理解已经发生变化。根据文章需要选择引用、短句留白、行动建议、信念判断或回环呼应，不添加固定号召。至少回答：

1. 现在可以确认什么；
2. 证据还不能支持什么；
3. 读者下一步可以做什么。

结尾不引入新主张，不用空泛总结替代闭环。

## 平易近人的写作姿态

把语气放在读者身边：像一个做过功课、亲自试过一些东西、也知道自己可能判断不全的同行在聊天。不要滑向导师训话、论文宣读、品牌宣传或全知旁白。

- **真实第一人称**：素材中有“我试过”“我踩过坑”“我不确定”“我更倾向于”时应保留，不要全部改成中性结论。没有作者经历时不冒充亲历者。
- **有判断但不居高临下**：明确表达喜欢、不喜欢、被打动、失望或倾向，同时交代判断来自什么经历或证据。用“我的判断是”承担主观性，不用“显然大家都应该”压住读者。
- **先理解再反驳**：先把另一种立场的合理处境具体讲出来，再给出不同判断。不要树立稻草人，也不要只截取真实人物有利于己方的片段。
- **情绪要有落点**：优先保留动作、停顿、身体反应、现场细节或一句当时真正说过的话，而不是笼统写“非常震撼”。情绪必须来自素材，不凭空制造。
- **承认边界**：教程、方法论和建议类文章可以坦率说明“还没完全跑通”“这部分仍在摸索”“初期可能比手工更慢”。真实的不确定感比假装全知更可信。
- **直接和读者说话**：只在需要拉近距离、提醒观察或邀请行动时使用“你可以先记住”“你也许会问”。不要每段都直呼读者。
- **使用圈内人的具体语言**：写代码就说真实命令、变量和失败日志，写游戏就用玩家实际会说的细节，写产品就给真实版本、按钮和操作路径。

## 节奏、段落与转场

- 一个段落只完成一个认知动作：提出问题、给直觉、举证、解释、转折或收束。
- 交替使用长短句和长短段。关键节点可以让一个短句或短语独立成段，给判断留出呼吸。
- 允许适度的“故意打破”：自然重复一个词、插入一句自我修正、短暂省略主语或让句子停一下。这些变化用于呈现真实思考，不用于故意写坏语法。
- 用疑问句充当刹车和转向：先把读者心里的问题问出来，再承诺用更直观的方式回答。
- 知识点在读者需要它时自然出现，像讨论到这里正好用得上；不要用“下面开始科普”切断文章。
- 标题只标记真实的问题转向或独立主题。保留仓库要求的必要标题，但段落之间优先用自然转场和扣主线句连接。
- 列表用于并列项和步骤，表格用于需要横向对齐的比较，admonition 用于值得打断主线的提醒。
- 避免“在当今……背景下”“首先、其次、最后”“综上所述”“值得注意的是”“下面介绍”等机械套话；能直接陈述时就直接陈述。
- 使用具体名词和主动动词，拆开过长名词串与多层定语。专业术语在首次需要时解释，不把大量定义前置成术语墙。
- 不按配额塞入口语词、短句、自嘲、疑问句或情绪标点。活人感来自真实材料和节奏变化，不来自词频统计。

## 推进与叙事技巧

- **层层剥开**：不要一上来公布全部结论。让读者依次经历现象、第一解释、更深问题、证据和洞察，看到判断怎样形成。
- **亲自下场**：有实验或体验材料时，展示作者实际做了什么、看到了什么、哪里失败、如何调整。过程本身就是证据。
- **英雄之旅**：调查或体验文章可以从具体召唤开始，经过尝试、困难、转折和收获，再带着变化回到原问题。没有真实过程时不要硬套。
- **反向论证**：先完整呈现读者原本合理的期待，再用事实打破，语气是“我原来也这样想”，不是“你们都错了”。
- **逐一展示与升番**：多个产品、模型或案例不要一口气报总结果。按基础、进阶、意外发现逐个展示，让后一项增加新的信息量；每项都要有具体观察，不只剩形容词。
- **微型故事**：工具、案例或技术效果可以按“挑战 → 想法 → 过程 → 结果”组织，让例子具有独立可读性。
- **回环呼应**：开头或中段出现的细节、问题或意象，后文应以新的含义回应。不要埋下与主线无关的装饰钩子。
- **自然升维**：只有当文化、历史、心理学或哲学参照能解释眼前问题时才引入，像顺着问题自然想到，而不是每篇强行拔高。
- **人物温度**：描写真实人物时使用来源确认的处境、动作和语言。使用典型画像或推测时明确标注，不能把想象当事实。
- **方法落地**：方法论每一节都让读者带走一个能执行的动作，同时说明学习曲线、时间成本和常见失败。

## 真实、具体与有边界

- 用来源中真实的人、对象、版本、数值、代码路径和实验条件支撑观点。
- 没有真实案例时使用明确标注的抽象小例子，不把它包装成真实经历。
- 敢于给判断，但区分事实、推导、偏好和建议。
- 解释一个方案时同时交代适用条件、学习成本、失败方式和反方合理处境。
- 引用知识是为了解决当前问题，不单独展示“查到了多少资料”。案例涉及真实人物时讲完整故事弧，不选择性裁剪。
- 保留素材里有辨识度的词、具体细节和情绪节点；只修复影响理解的口语，不把作者声音磨平成统一的 AI 书面语。

## 图文协作

每张图只解决一个清晰的阅读障碍。图前说明为什么要看，图后说明应观察什么以及证据边界。

图只是装饰、重复相邻文字、需要比正文更久才能看懂，或打断主线时，应删除或重画。不要为达到图片数量、面板数量或工具覆盖率而配图。

## 四层校验

按顺序执行。前一层不通过时先修复，不用后层主观感受掩盖硬错误。

### L1 硬边界

检查事实、来源、保真、隐私、敏感信息、front matter、Markdown 结构、链接、图片和既有内容保全。自动扫描只能辅助，最终以实际语义为准。

### L2 结构与节奏

逐节回答：

- 开头是否快速建立问题与阅读承诺；
- 标题是否组成自然的问题链；
- 每节是否有明确答案，并能接到下一节；
- 补充材料是否及时回到主线；
- 长短句、长短段、疑问转向和独立短句是否形成自然节奏；
- 是否存在同义重复、列表堆叠、连续句式呆板、过长段落或突兀图片；
- 是否有一段删除后主线反而更清楚。

### L3 内容质量

检查核心观点是否有具体证据或例子，知识是否在需要时自然出现，术语是否及时解释，技术深度是否匹配主线，比较是否使用相同边界，行动建议是否包含代价与失败条件，反方处境是否被公平呈现，结论是否超出证据。

按文章原型执行专项检查：调查与体验是否有真实过程和层层发现；现象解读是否由观察推进到洞察；工具分享是否有实际场景与结果；方法论是否给出行动、学习曲线和失败点；多案例比较是否逐一展示而不是只报总表。

### L4 活人感与心流终审

暂时忘记写作过程，以目标读者身份从头读到尾。先回答一个总问题：这像一个有见识、有实践、愿意承认边界的人在认真聊天，还是一台 AI 在整理信息？随后标记：

- 注意力中断的位置；
- 需要回读才能理解的位置；
- 像报告、目录或 AI 汇总而不像文章的位置；
- 真实第一人称、具体细节和情绪被磨平的位置；
- 语气突然变化、假装亲历、导师训话或品牌营销的位置；
- 只有正确结论却看不到作者判断与形成过程的位置；
- 没有理解反方处境就直接下判断的位置；
- 开头问题没有在结尾闭合的位置。

读出声或逐段复述主旨能暴露更多断点。L4 不统计口语词、短句、问号、自嘲或修辞数量，而是判断温度、独特性、姿态和整篇心流。没有真实个人材料的文章可以克制，但不能冷硬、空泛或假装客观到没有任何判断。

## 返工方式

每轮只列最影响阅读的 1 至 3 个问题，记录位置、原因和动作：

```text
位置 -> 读者为何卡住 -> 删除 / 前移 / 后移 / 拆分 / 合并 / 补桥 / 降级结论
```

修复后从文章开头重新通读，不只复查局部。存在以下任一情况时不得定稿：

- 导言结束后仍说不出文章主线；
- 连续两节之间缺少可解释的推进关系；
- 关键结论需要读者自己补出中间推理；
- 某节只为满足模板而存在；
- 公式、表格、代码或图片替代了应有的自然语言解释；
- 结尾没有回答开头，或突然出现新结论。

质检报告保持简短，只报告失败项、已执行修复和仍存在的边界。
