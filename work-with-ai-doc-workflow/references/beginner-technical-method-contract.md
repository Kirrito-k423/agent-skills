# 初学者技术机制解释契约

文章解释命名概念、算法、优化、架构路径、框架后端或实现技术时阅读本契约。

## 解释目标

让读者先建立稳定的物理直觉，再逐步接触术语、对象、shape、通信、公式和实现。**解释完整不等于把后台分析全部倒进正文。**

先在后台完成机制账本，再按当前文章的核心问题选择必要内容。方法只是背景时用一段话讲清作用与边界；方法本身是主题时才展开完整机制。

## 区分三个层次

每个重要结论都要知道属于哪一层：

1. **抽象概念**：不依赖某个代码库的问题与思路。
2. **可复用机制**：哪些对象被切分、移动、复制、聚合、重算、保留或提前释放。
3. **框架实现**：固定版本中的文件、符号、配置开关和实现特有行为。

不要把分支上的局部生命周期修复写成通用算法，也不要用论文结果证明某个框架补丁具有相同数值收益。

## 构建机制主线

优先使用下面的认知顺序，但不要机械地把每一项变成标题：

1. **问题现场**：原方法在哪里遇到内存、计算、通信、正确性或可用性瓶颈。
2. **一句直觉**：不用缩写，说明方法做了什么物理动作。
3. **最小例子**：用小 tensor、少量 Rank、一个 cache 或一次状态更新展示变化。
4. **关键对象与过程**：只引入理解机制所需的输入、输出、权重、状态、workspace 和通信对象。
5. **实现与证据**：指出通用机制如何落到固定版本源码，以及来源证明到哪里。
6. **效果与代价**：说明改善的对象、新引入的成本、适用条件和失败边界。

每一段都回答一个自然问题，并把读者带向下一问。背景知识放在首次需要它的位置，不单独堆成百科式前置章节。

## 后台对象账本

为核心对象记录：

```text
对象 -> 来源 -> shape / dtype -> 所在设备或 Rank -> 消费者 -> 生命周期 -> 是否实际物化
```

正文只展示支撑当前解释的对象，但不得因此产生未定义符号、静默 shape 变化或错误的存储印象。涉及并行、offload、cache 或 state 时，必须回答：

- 什么留在本地；
- 什么移动；
- 什么被复制；
- 什么被聚合或归约；
- 什么在何时释放或跨步骤保留。

## 伪代码与公式

只有当自然语言不足以明确顺序、分支、shape 或状态变化时才加入伪代码。伪代码需要展示当前机制的关键路径，包括适用的切分、reshape、transpose、通信、本地计算、合并、归约、状态写入和输出。

允许省略与机制无关的日志、参数校验和样板代码，并标明省略内容。不得省略会改变正确性、内存峰值、通信语义或输出的步骤。

公式先讲语义，再讲符号和 shape。语义等价式与真实运行路径不同时，两者都要说明，并指出哪些对象只是代数视图。

## 按障碍选择图形

图形数量由认知障碍决定，不由模板决定：

- **前后对比**：读者看不清对象大小、位置或生命周期如何改变。
- **因果逻辑**：读者看不清“瓶颈—机制—直接效果—新代价”。
- **流程图**：读者看不清步骤、分支、循环或同步点。
- **时序图**：多 Rank、多组件、异步传输或对象生命周期是关键。
- **数据流图**：tensor shape、算子、cache 或 state 路径是关键。

一张图可以承担多个相容角色，但不要为了角色齐全而拼接难以阅读的五联图。正文必须在图前说明它解决什么问题，在图后指出读者应该观察什么。

## 效果边界

分析显存峰值时使用同一账本：

```text
M_peak =
    M_model_state
  + M_saved_activations
  + M_operator_workspace
  + M_communication_buffers
  + M_live_inputs_and_outputs
  + M_allocator_reserved_unused
  + M_runtime_margin
```

说明方法是在**减少大小、设置上界、转移位置、缩短生命周期**，还是仅清理 allocator 缓存。随后说明：

1. 直接作用于哪一项；
2. 近似随什么变量变化；
3. 哪些固定项、复制缓冲或 workspace 阻止严格成比例；
4. 新增的计算、传输、同步、host 内存、碎片或吞吐成本；
5. 报告数值收益需要控制哪些实验条件。

没有同一运行条件下的测量时，只给理论方向，不给精确节省比例。跨论文数字必须保留硬件、模型、精度、拓扑和 baseline 边界。

## 接受门槛

出现以下任一情况时返工：

- 先堆术语，读者还不知道旧方法遇到了什么问题；
- 表格、公式、伪代码或总览图替代了关键机制解释；
- 抽象概念、通用机制和框架补丁混为一谈；
- 多 Rank、cache、state 或 offload 的位置与生命周期需要读者猜测；
- 效果只讲收益，不讲代价、条件和证据边界；
- 为了“完整”加入与文章主线无关的对象、视图或实现细节；
- 章节读完后，读者仍无法用自己的话解释方法改变了哪个对象、怎样改变以及为什么有效。
